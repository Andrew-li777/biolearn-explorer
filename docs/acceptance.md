# 实施顺序与验收

## 五阶段

1. 数据：固定公开来源、建立自包含快照、类型与来源映射，校验数值和图像哈希。
2. 框架：首页、设计系统、导航、主题、响应式骨架。
3. 专业模块：四项目分别实现专属页面、真实图像及摘要交互。
4. 解读：方法复现、公开案例、正逆证据浏览与 About。
5. 质量：交互、无障碍、双主题、性能、三种部署场景验证与交付文档。

每阶段写本目录 docs/progress.md，区分完成、计划、阻塞、未验证。不得在数据缺失时用随机点补齐验收。

## 功能与科学准确性

- 八页面可访问，关键文案和参数可追溯，运行/核验/构建日期分开。
- 数字来自快照适配层，无未映射的科研常数；比较方向、阈值与分母一致。
- 7 张来源图哈希一致；静态图片无假筛选；Ubi4 图不被错误映射为其他组。
- 两例报告摘录标明范围；不把案例搜索当作全表搜索；不把跨工具一致性作为独立实验验证。
- 未公开产物既无伪造下载也无错误 GitHub 文件链接。
- 主题、筛选、检索、排序、方法切换、图片查看/全屏/下载、命令复制、来源详情、空状态均有真实行为。

## 自动化与人工检查

Vitest：摘要适配、来源状态、精度、筛选/排序、缺字段失败、错哈希、未公开链接处理。Playwright：8 个页面、分享刷新、主题、键盘、模态框焦点、筛选/下载、无数据状态；检查控制台及资源 404。

在 390、768、1440px 下检查双主题，无非预期横向溢出；表格可以有明确的局部横向滚动。图像不裁切坐标，文字可读；视觉截图和测试报告保存在本目录。

分别构建 / 与 /测试仓库名/ 两种 base，在静态服务器检查资源、hash 路由、图片与下载；根路径成功不代表子路径成功。

把前端文件复制到不含父分析仓库的干净目录后，执行 npm ci、数据校验、类型检查、测试、build 和 preview。记录完整版本与命令。离线运行已有 dist 不请求 GitHub 或依赖外部字体。

性能按架构文档预算实测。尚未取得服务器时仅标记配置就绪；实际 GitHub Pages/Cloudflare/服务器部署各自独立记录结果，不能将模拟测试写成线上验证。

## 最终网站交付

完整源码与锁文件、自包含公开数据与图片、来源映射、运行 README、配置化部署说明、测试与性能记录、已实现/数据不足暂不可用功能清单。发布和创建远端另依用户授权执行。

## 本轮文档交付验收

本轮不运行以上网站测试；只检查文件链接、需求覆盖、来源清单和写入边界。提示词与辅助文档不得出现“网站已完成”或“线上性能已达标”的陈述。
